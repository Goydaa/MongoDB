# Основные понятия MongoDB

**Дата: 11.09.2026**

## 1. Документ

**Документ** — основной элемент хранения информации в MongoDB. По назначению он похож на строку в реляционных базах данных, например PostgreSQL, но данные в MongoDB представлены в формате BSON (Binary JSON).

Документы имеют гибкую структуру: в одной коллекции могут находиться записи с разными наборами полей. Поэтому при добавлении документа необязательно указывать все возможные поля.

Информация в документе организована в виде пар «ключ — значение».

Каждый документ содержит поле `_id`, которое служит его уникальным идентификатором внутри коллекции. Если пользователь не задаёт это поле самостоятельно, MongoDB создаёт его автоматически.

## 2. Коллекция

**Коллекция** — это группа документов. В реляционных базах данных её ближайшим аналогом является таблица.

Основные особенности коллекций:

- Для начала работы не требуется заранее задавать строгую схему данных.
- Документы обычно относятся к одной предметной области, но могут иметь различную структуру.
- Коллекция может быть создана автоматически при первой записи документа.
- Для ускорения поиска и обеспечения уникальности данных можно создавать индексы, в том числе составные и уникальные.

### Структура хранения данных

**База данных → Коллекция → Документ → Поле**

## 3. BSON

**BSON (Binary JSON)** — бинарный формат представления и сериализации данных, основанный на структуре JSON и расширяющий её дополнительными типами.

BSON хранит информацию о длине документа и отдельных значений, что позволяет эффективнее обрабатывать структуру данных. Однако это не означает, что любая операция с BSON обязательно быстрее аналогичной операции с JSON.

BSON поддерживает типы данных, которые отсутствуют в стандартном JSON:

- `ObjectId` — уникальный идентификатор документа.
- `Date` — дата и время.
- `Binary` — двоичные данные.
- `Decimal128` — число с высокой точностью.
- `Regular Expression` — регулярное выражение.
- `JavaScript` — значение, содержащее JavaScript-код.

### Структура BSON-документа

В упрощённом виде документ BSON состоит из следующих частей:

`<размер документа (4 байта)> <элементы> <нулевой байт>`

Каждый элемент включает:

`<тип значения (1 байт)> <имя поля> <значение>`

**Особенности BSON:**

- BSON может занимать больше места, чем текстовый JSON, из-за дополнительных служебных данных.
- Для значений используются разные типы, например `int32`, `int64` и `double`.
- Тип данных влияет на то, как значение хранится, сравнивается и обрабатывается.

## 4. Типы полей и структура документов

### 4.1. Скалярное поле

**Скалярное поле** — поле, в котором хранится одно простое значение: строка, число, логическое значение, дата или идентификатор.

Пример:

```json
{
  "name": "Алексей",
  "age": 28,
  "active": true
}
```

В этом примере `name`, `age` и `active` — скалярные поля с разными типами значений.

### 4.2. Вложенный документ

**Вложенный документ** — это объект, который хранится в качестве значения другого поля. Он позволяет объединять связанные данные внутри одной записи.

Такой подход удобно использовать, когда сведения логически связаны между собой, например при хранении адреса пользователя.

Пример:

```json
{
  "name": "Алексей",
  "address": {
    "city": "Казань",
    "street": "Баумана",
    "zip": "420000"
  }
}
```

Здесь поле `address` содержит отдельный документ с информацией об адресе.

**Особенности вложенных документов:**

- Документы могут содержать вложенные объекты на нескольких уровнях; максимальная глубина вложенности в MongoDB — 100 уровней.
- При сравнении вложенных документов целиком порядок полей имеет значение.
- К отдельным вложенным полям можно обращаться через точечную нотацию, например `address.city`.

### 4.3. Массив

**Массив** — поле, содержащее упорядоченный список значений. Его элементами могут быть строки, числа, вложенные документы и другие массивы.

Массивы подходят для хранения перечней связанных с документом данных, например увлечений человека или его заказов.

Пример:

```json
{
  "name": "Алексей",
  "hobbies": ["футбол", "музыка", "путешествия"],
  "orders": [
    { "id": 1, "sum": 150 },
    { "id": 2, "sum": 320 }
  ]
}
```

В этом примере поле `hobbies` содержит список строк, а поле `orders` — массив документов с информацией о заказах.

Массивы позволяют хранить несколько значений в одном поле и обращаться к их элементам при выполнении запросов MongoDB.
